## 2. プロジェクト概要

### 2.1 背景
スイングトレードでは、多数の上場銘柄の財務状況・チャート・テクニカル指標を日々確認する必要があり、投資判断に多くの時間を要する。また、全指標を単純合算する従来のスコアリング手法では、「企業や長期トレンドは良いが今が買い時ではない（高値圏で伸び切った）銘柄」と「今まさにエントリー準備が整った銘柄」が混在してしまう課題があった。

本プロジェクトでは、東証上場銘柄の中から一定の財務・流動性基準と中長期の上昇トレンドを満たす銘柄を絞り込み、**「押し目買い」または「保ち合い上抜け（ブレイクアウト）」のセットアップにある有望銘柄を1次スクリーニングとして定量抽出するシステム**を開発する。抽出された銘柄および構造化データ（具体的なサポレジ価格水準や各種スコア）を後段のAI（またはトレーダー自身）へ引き渡すことで、具体的な買値（指値・逆指値）・損切りライン・エントリータイミングの意思決定を高度化・効率化する。

### 2.2 目的
- スイングトレードにおける銘柄選定（1次スクリーニング）を自動化し、分析時間を大幅に短縮する。
- 「環境認識（前提条件の足切り）」と「エントリーセットアップ（押し目・上抜け）」を分離した段階的評価により、実際にプラスのリターンになりやすい（期待値・勝率の高い）買い候補銘柄を一貫した基準で抽出する。
- 後段のAIが買値や損切り水準を判断するために必要な定量データ（各種スコア、判断根拠、現在値・移動平均線・直近高安・ボラティリティ等の価格水準）を構造化して出力する。
- 任意の過去基準日を指定したフォワードリターン検証（答え合わせ）を可能にし、スクリーニング条件や重み付けを客観的データに基づいて継続改善できるようにする。

### 2.3 ゴール
プログラムを実行すると、東京証券取引所の上場銘柄から事前条件（市場区分・財務・流動性）およびテクニカル環境条件（上昇トレンド）を満たす銘柄が絞り込まれ、「押し目買い型」「ブレイクアウト型」の推奨銘柄ランキングと構造化レポート（JSON / Markdown）が出力されること。

各推奨銘柄について、少なくとも以下の情報を確認・連携できること。
- 銘柄基本情報（銘柄コード、銘柄名、市場区分、業種）
- 推奨戦略区分（「押し目買い型」または「ブレイクアウト型」）および代表戦略スコア
- 買い判断の根拠サマリー（どの条件・特徴量・パターンが評価されたか）
- 後段AI連携用の具体的な価格水準・リスク指標（現在値、SMA5/25/75価格、直近20日高値・安値、ATR/ボラティリティ、出来高倍率、主要財務指標）
- 算出された各特徴量スコアおよび検出されたチャートパターン

### 2.4 対象ユーザー
- 本システムの主たる対象ユーザーは開発者本人（および後段で連携するAIエージェント）とする。
- 将来的な条件調整や戦略追加が容易に行えるよう、設定ファイル駆動かつ拡張性・保守性の高いモジュール設計とする。

## 3. システム概要

### 3.1 システム構成
本システムは、データ取得から事前フィルタ、テクニカル分析、戦略別スコアリング、スクリーニング・検証、レポート出力までを責務ごとに分離したモジュラー・モノリス構成とする。

- **Data Collector**
  - 東証銘柄マスタ、株価・出来高データ（OHLCV）、財務データ（IR BANK JSON）の取得・キャッシュ・永続化
- **Pre-Screener (Universe Filter)**
  - 銘柄マスタ・財務データ・売買代金（流動性）に基づく分析対象ユニバースの事前絞り込み
- **Indicator Calculator**
  - 移動平均線（SMA）、RSI、MACD、ATR等のテクニカル指標の算出
- **Feature Engine**
  - トレンド、移動平均配列、押し目、ブレイクアウト、出来高、モメンタム、ボラティリティ、ファンダメンタルズ等の特徴量（0〜100）の算出
- **Pattern Detector**
  - ダブルボトム（押し目底打ち確認用）、ダブルトップ（弱気除外・減点用）、ローソク足パターンの検出
- **Score Engine**
  - 「押し目買い戦略スコア」および「ブレイクアウト戦略スコア」の算出、弱気シグナルの減点、代表スコアと推奨戦略タイプの決定
- **Screener & Ranking**
  - 第1関門（中長期上昇トレンド）・第2関門（セットアップ基準スコア）による買い候補銘柄の抽出と、代表スコア順のランキング生成
- **Evaluator (Forward Return Validator)**
  - 過去基準日指定時のフォワードリターン（N営業日後の騰落率・勝率・最大上昇/下落幅）の計測・集計
- **Presentation**
  - 分析結果のCLI表示、および後段AI連携用の構造化ファイル（JSON / Markdownレポート）の出力

### 3.2 システムで実現すること
- 東証プライム・スタンダード市場を中心とした銘柄から、財務・企業規模・流動性の基準を満たす分析対象銘柄を自動抽出する。
- 基準日（`as_of_date`）時点のデータに基づき、未来データのリークなくテクニカル指標・特徴量・チャートパターンを算出する。
- 中長期が上昇トレンドにある銘柄を対象に、「押し目買い型」「ブレイクアウト型」の2つの買い戦略で評価・スコアリングし、推奨銘柄をランキング出力する。
- 後段のAIが買値・損切りラインを算出するための具体的なサポレジ価格水準・リスク指標と判定理由を構造化ファイル（JSON / Markdown）として出力する。
- 過去の任意基準日を指定してスクリーニングを実行し、抽出銘柄のその後の実リターン（5日後・20日後・60日後など）を検証できる。

### 3.3 対象外とすること
本システムでは以下は対象外とする。
- 空売り候補（戻り売り・下落ブレイク）の抽出および保有銘柄の売り時判定
- 最終的な指値・逆指値価格の決定および自動売買注文の実行（買値・タイミングの最終判断は後段のAIおよび人間が担う）
- 証券会社とのリアルタイムAPI連携・板情報配信
- GUI（Streamlit等のWebダッシュボード）およびプッシュ通知・アラート機能
- 複雑な資金管理・複数年ポートフォリオ売買執行を伴うフルバックテストシミュレーター

## 4. 分析・評価要件（3段階ゲート＋戦略別スコア方式）

### 4.1 売買スタイルと基本戦略
- **売買手法**: 現物買いによるスイングトレード（保有期間目安：数週間〜3か月）。
- **対象銘柄**: 東証プライム・スタンダード市場を中心とした中〜大型株（流動性が高く機関投資家の参入があり、テクニカル分析が機能しやすい銘柄群）。
- **エントリー方針**: 戻り売りの壁（しこり玉）が多い下降トレンドからの逆張りは避け、勝率と資金効率が安定しやすい**「中長期上昇トレンド中の押し目買い」**および**「上昇トレンド・保ち合いからの上抜け（ブレイクアウト）」**の2本柱をターゲットとする。

### 4.2 段階的スクリーニング＆評価フロー
1. **事前スクリーニング（Universe 抽出）**
   - **市場・規模・財務フィルタ**: 東証銘柄マスタとローカル財務データ（`data/financial/`）を用い、通信前に「対象市場（プライム・スタンダード）」「一定の売上・資産規模」「営業黒字・純利益黒字・ROE基準・自己資本比率基準（債務超過や危険銘柄の排除）」で対象銘柄を絞り込む。
   - **流動性フィルタ**: 対象銘柄のOHLCVデータを取得・更新し、直近（例：20営業日平均）の売買代金・出来高が基準以上の銘柄のみを通過させる。
2. **第1関門：環境認識フィルタ（上昇トレンド前提条件）**
   - 移動平均線配列（`M001: MAAlignmentScore`）やトレンド強度（`T001: TrendStrengthScore`）が基準値以上であり、株価が中長期移動平均線（SMA75等）の上方で推移していることを必須条件とする。
   - 天井圏の転換パターン（`R002: DoubleTop`）が成立している銘柄や、ボラティリティが異常過熱している銘柄は除外または大幅減点とする。
3. **第2関門：セットアップ判定（2大買い型の抽出）**
   - **押し目買い型（Pullback Setup）**: 上昇トレンドの中で中期線（SMA25等）付近まで調整・接近している状態（`P001: PullbackScore` が基準以上）。`R001: DoubleBottom` や下ヒゲ（`Hammer`）、モメンタム反転（`O001: MomentumScore`）を反発の裏付けとして評価する。
   - **ブレイクアウト型（Breakout Setup）**: 直近高値（過去20日高値等）への接近または上抜け初動にある状態（`P002: BreakoutScore` が基準以上）。出来高急増（`V001: VolumeScore`）を伴うものを高く評価する。
4. **第3関門：戦略別スコアリングとランキング**
   - 「押し目買い戦略スコア」と「ブレイクアウト戦略スコア」をそれぞれの重み付けルールで算出し（ファンダメンタルズ評価 `F001〜F005` は補助加点として反映）、高い方のスコアとその戦略タイプを銘柄の代表値として採用し、降順でランキングを生成する。

### 4.3 出力内容
分析結果として、各推奨銘柄について以下の情報をCLI表示および構造化ファイル（`output/` 配下の JSON / Markdown）へ出力する。
- **基本情報**: 銘柄コード、銘柄名、市場区分、業種、評価基準日（`as_of_date`）
- **戦略評価**: 推奨戦略区分（`押し目買い型` / `ブレイクアウト型` / `監視`）、代表スコア、戦略別サブスコア、買い判断の根拠サマリー
- **AI連携用・価格水準＆リスク情報**:
  - 現在終値、SMA5 / SMA25 / SMA75 の各価格と現在値からの乖離率（%）
  - 直近20日最高値・最安値（レジスタンス・サポート目安）
  - ボラティリティ指標（ATR または日次変動率、出来高倍率）
  - 主要財務指標（PER、PBR、ROE、売上・利益成長率）
- **詳細内訳**: 各特徴量（Feature）のスコア・生値、検出されたチャートパターン（Pattern）と信頼度
- **検証結果（過去基準日検証モード時のみ）**: 基準日から N営業日後（例：5日後、20日後、60日後）の騰落率（%）、期間内の最大上昇率（MFE）・最大下落率（MAE）、全体の勝率・平均リターン集計

## 5. 機能要件

### 5.1 データ管理・取得機能
- 東証上場銘柄マスタ（コード、銘柄名、市場区分、業種、規模区分）を `data/` 配下に保持・参照できること。
- 株価データ（OHLCV）を取得し、Parquet形式でローカル保存・差分更新できること。
- `data/financial/` 配下の財務JSONデータ（IR BANK形式：PL/BS/CF/配当）を読み込み、単年指標および複数年成長率（CAGR）を算出できること。
- 基準日（`as_of_date`）を指定した際、その基準日時点までのデータのみを切り出して後続モジュールへ渡し、先読みバイアス（未来データのリーク）を防止できること。

### 5.2 事前スクリーニング機能（Pre-Screener）
- OHLCV取得前に、銘柄マスタの市場区分およびローカル財務データの数値条件（黒字、ROE、自己資本比率、売上規模等）で分析対象ユニバースを高速に絞り込めること。
- OHLCV取得後に、直近平均売買代金・出来高による流動性フィルタを適用できること。
- 各種フィルタ閾値は設定ファイル（YAML等）から変更可能であること。

### 5.3 テクニカル指標・特徴量・パターン算出機能
- 移動平均線（SMA5/25/75等）、RSI、MACD、ボラティリティ（ATR等）、直近高安値を算出できること。
- 算出済みのテクニカル特徴量（`M001`, `P001`, `P002`, `T001`, `V001`, `O001`, `R001`）およびファンダメンタルズ特徴量（`F001〜F005`）を0〜100のスコアとして定量化できること（旧計画の `R002: RiskScore` および `S001: SupportResistanceScore` は独立特徴量から廃止し、Score Engine・出力層のサポレジ価格水準・リスク情報へ統合する）。
- チャートパターン（`R001: DoubleBottom`, `R002: DoubleTop`, `Candlestick`）を検出し、買いの裏付けまたは除外・減点材料として提供できること。

### 5.4 戦略別スコアリング・本スクリーニング・ランキング機能
- 第1関門（中長期上昇トレンド条件および弱気シグナル除外）と第2関門（押し目買い型／ブレイクアウト型のセットアップ条件）を満たす銘柄をフィルタリングできること。
- 「押し目買い戦略スコア」と「ブレイクアウト戦略スコア」を重み付け算出し、高い方を代表スコアおよび推奨戦略タイプとして決定できること。
- 推奨理由（どの特徴量・パターンが寄与したか）を自然言語テキストおよび構造化データとして生成できること。
- 代表スコア順（または指定した戦略タイプ別）に上位N件のランキングを生成できること。

### 5.5 レポート出力機能（CLI / ファイル出力）
- 分析結果をCLI（標準出力）で見やすく一覧表示できること。
- 後段のAIへそのままプロンプトやコンテキストとして渡せるよう、`output/` ディレクトリへ **JSON形式** および **Markdown形式** のレポートファイルを出力できること。

### 5.6 スクリーニング精度検証（フォワードリターン評価）機能
- CLI引数等で過去の基準日（`as_of_date`）と検証モードを指定して実行できること。
- 基準日時点で抽出された推奨銘柄について、基準日以降のキャッシュ済みOHLCVデータを参照し、指定営業日後（デフォルト：5営業日・20営業日・60営業日）のリターン（騰落率）、期間内最大上昇率（MFE）、最大下落率（MAE）、および抽出銘柄全体の勝率・平均リターンを算出・出力できること。

## 6. 非機能要件

### 6.1 性能・効率性
- 全上場銘柄（約4,000銘柄）に対する市場区分・財務事前フィルタはローカルJSONを用いて数秒以内に完了し、不要な外部API通信を発生させないこと。
- 取得済みのOHLCVデータ（Parquet）および計算キャッシュを活用し、2回目以降の同日分析や過去基準日検証を高速に実行できること。

### 6.2 保守性・設定容易性
- スクリーニングの閾値（売買代金、ROE、トレンドスコア下限等）や戦略別スコアの重み付けは、ハードコードせず設定ファイル（`config/` 配下の YAML 等）または設定クラスで一元管理し、チューニングが容易であること。
- 単一障害で全体が停止しないよう、個別銘柄のデータ欠損や取得エラー時は警告ログを出力して該当銘柄をスキップし、パイプライン全体の処理を継続できること。

### 6.3 拡張性
- `IFeature`, `IPattern`, `IScoreCalculator` のレジストリ構造を維持し、新しい特徴量や新しい買い戦略を既存コードを壊さずにプラグイン追加できること。

### 6.4 テスト容易性・再現性
- 同一の入力データ・基準日・設定に対して常に同一のスコアおよび抽出結果が算出される（決定論的である）こと。
- 各モジュールに対する単体テストおよびパイプライン結合テストが `pytest` で自動実行可能であること。

## 7. データ要件

### 7.1 利用データとデータソース
- **銘柄マスタ**: 東証上場銘柄一覧（銘柄コード、銘柄名、市場区分、33業種/17業種区分、規模区分）。
- **株価・出来高データ（OHLCV）**: Yahoo Finance (`yfinance`) から取得する日足データ（始値、高値、安値、終値、出来高）。
- **財務データ**: IR BANK 形式の年度別 JSON データ（貸借対照表 `fy-balance-sheet.json`、損益計算書 `fy-profit-and-loss.json`、キャッシュフロー計算書 `fy-cash-flow-statement.json`、配当 `fy-stock-dividend.json`）。

### 7.2 保持データと保存形式
- `data/master/`: 銘柄マスタデータ（CSV または JSON / Parquet）
- `data/price/`: 銘柄別の日足OHLCVデータ（Parquet形式、`{symbol}.parquet`）
- `data/financial/`: 年度別の全銘柄財務データ（JSON形式）
- `data/cache/`: 指標・特徴量の計算キャッシュ（JSON / Parquet形式）
- `output/`: スクリーニング結果および検証レポート（JSON形式・Markdown形式）

### 7.3 更新タイミング
- 株価データ（OHLCV）：日次（大引け後または分析実行時に未取得期間を差分取得）。
- 財務データ・銘柄マスタ：決算期または定期（月次〜四半期単位でのキャッシュ更新）。

---

## 8. 制約条件
- 外部データ取得（Yahoo Finance 等）においてはアクセス頻度制限（レートリミット）を考慮し、ローカルParquetキャッシュおよび事前スクリーニングによる通信対象の最小化を行うこと。
- 株式分割や上場廃止等による異常値・データ欠損が含まれる可能性があるため、異常値ハンドリングを行うこと。
